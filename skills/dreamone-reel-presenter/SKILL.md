# 方塊動畫＋真人講解 Reel

一支成品由兩個人各做一半：**動畫**（程式算出來的方塊、算式、逐句字幕）和**講師的自拍講解**。
這份流程把兩半合成一支：講師愛怎麼講就怎麼講，動畫的快慢回頭配合人聲。
流程從 2026 年 11 月的 01〈上帝的數字 20〉做出來，那支來回改了五版，下面的規則和預設值都是被退回過才定下的。

## 0. 四條不能破的規則

1. **人像不能擋到字幕或動畫主體。** 用眼睛看不準，要量（第 8 節）。01 的圓框先後因為「擋到動畫」「擋到文字」各被退回一次。
2. **人臉比例不能變形。** 手機直拍的素材常是「橫的畫面＋90 度旋轉旗標」，處理時一律當直式 1080×1920（`references/lessons.md` 第 1 條）。
3. **剪接點要落在安靜處。** 不能有字被切到，不能帶進上一次 NG 的尾巴。語音辨識的時間不夠準，一定要跑 `snap.py`。
4. **交件前自己用量測把關，並老實說哪些沒辦法判斷。** AI 聽不到聲音：切點、響度、字幕遮擋可以量，配樂好不好聽、語氣自不自然只能由人來聽。

## 1. 編號與片單

每一支影片有一個兩位數編號，**溝通一律講編號**——題目相近的片用文字講容易搞混。

- 片單在 [`docs/videos.md`](../../docs/videos.md)：編號、片名、狀態、長度、配樂。有人問「有哪些影片」「03 做到哪了」，讀這個檔回答；狀態有變就更新並 commit。
- 新動畫一進來就先取號（接在片單最後一號後面），不要等做完。
- 本機一支片一個資料夾：`NN_片名/`，裡面放動畫專案、`cuts.json`、素材、`旁白.mp4`、各版成品。定稿命名 `NN_片名_定稿.mp4`。
- 原始素材（講師的 MOV）也放進這個資料夾的 `素材/`，並提醒使用者定稿前不要刪——01 的素材在定稿後被清掉，之後就沒辦法換取樣重剪了。

## 2. 流程總覽

| 步驟 | 做什麼 | 工具 |
|---|---|---|
| 1 | 從 GitHub 拿動畫、取號、匯出一版給講師看 | `git clone`、動畫專案自己的預覽頁 |
| 2 | 給講師逐字稿和錄影須知 | 從動畫的字幕整理 |
| 3 | 把錄影抄成帶時間碼的逐字稿 | `scripts/transcribe.py` |
| 4 | 每一句挑最好的一次，寫成 `cuts.json` | 唯一需要判斷力的步驟 |
| 5 | 剪接點對到安靜處 | `scripts/snap.py` |
| 6 | 接旁白、變速、算出動畫的新時間軸 | `scripts/assemble.py` |
| 7 | 動畫照新時間軸重新匯出 | 動畫專案的預覽頁 |
| 8 | 疊人像圓框與名牌 | `scripts/pip.sh` |
| 9 | 墊配樂、校響度，出幾版讓講師挑 | `scripts/music.sh` |
| 10 | 驗收、交付、把修改推回 GitHub | 第 10 節的清單 |

安裝與每支工具的參數見 [README.md](README.md)。

## 3. 拿動畫（步驟 1）

動畫專案放在 GitHub，**直接 clone，不要經過雲端硬碟的 zip**：zip 是單向快照，這邊對動畫的修改回不去，下一支又要重做。

1. `git clone` 到 `NN_片名/` 底下，`npm install`。
2. 確認專案有接時間軸掛鉤（`src/timing.js`）。沒有就照 [`references/animation-hook.md`](references/animation-hook.md) 接上，開分支、推回去。
3. 啟動預覽、匯出一版原速的 MP4 給講師看。匯出會覆蓋 `out/` 裡同名的檔案，**先把原本的那支備份**。
4. 在片單登記編號。

## 4. 逐字稿與錄影須知（步驟 2）

逐字稿就是動畫上的那幾句字幕，一句一段編號，數字寫成國字（「二十步」「四千三百二十五京」），畫面上會變色的關鍵詞標粗體。

給講師的須知只有這些，其他都不用管：

- **直式拍**，人在畫面中間，上半身和手都入鏡。
- 照自己的節奏講，**NG 就重講那一句，不用停錄、不用記哪次好**。
- 句子可以照自己的話講，不必跟字幕一字不差。
- 結尾的 CTA 可以另外錄一支短的。
- 定稿前不要刪原始檔。

不需要句子之間刻意停頓——挑取樣靠語音辨識，不靠停頓。

## 5. 抄稿與挑取樣（步驟 3、4）

```bash
python scripts/transcribe.py 素材/主檔.MOV --script 逐字稿.md
```

讀辨識稿，為每一句找出**最完整、通常是最後一次**的取樣，寫成 `cuts.json`（格式見 `cuts.example.json`）。秒數填大概的範圍即可，但範圍不要包到前一次或後一次的 NG。

挑的時候注意：

- 講師常在句首加發語詞再停頓很久才講正文（01 的第 9 句：「不過」之後停了十秒）。辨識稿會把整段標成一句，要看字詞時間找正文真正開始的地方。
- 同一句連講兩次、中間沒停的話，辨識稿的字詞時間會糊在一起（01 的第 7 句）。這種一定要靠下一步的音量來分。
- `聽到的` 欄位填講師實際講的話，之後回讀驗證要對這個。
- 逐句對照畫面上的字幕和數字。**每一次都講錯的口誤**（02 的「三乘三」）剪不掉，先問講師要補錄還是試剪接；剪接的做法見 `references/lessons.md` 第 19 條。

## 6. 對切點、接旁白（步驟 5、6）

```bash
python scripts/snap.py NN_片名/cuts.json --write
scripts/assemble.py NN_片名/cuts.json
```

`snap.py` 在每一段的範圍裡量音量，找出真正開口和收尾的位置，前留 0.10 秒、後留 0.14 秒，並回報有沒有切在有聲音的地方。**報告要全部「乾淨」才往下走**；出現 ⚠ 就照提示把範圍往前或往後移。

`assemble.py` 接出 `旁白.mp4`（已變速），把新時間軸寫進動畫的 `timing.js`，並把疊人像要用的 `START`、`END` 存進 `旁白.json`。

接完**馬上回讀一次**：`transcribe.py 旁白.mp4`，逐字對 `聽到的`。多一個字、少一個字都要回頭查——01 第一版回讀其實已經顯示句首多了半個字，當時沒逐字看就漏掉了。

句與句黏太緊、句尾的字聽起來像下一句的開頭時，在前一句加 `"後停": 0.3`。

## 7. 重新匯出動畫（步驟 7）

`timing.js` 更新後，動畫的成品長度會變成旁白的長度。啟動預覽頁、匯出，匯出檔改名成 `動畫_配合旁白.mp4`，再把備份的原版放回去。

因為整支動畫是「給秒數就畫出那一格」的程式，改時間軸只是換算時間，方塊轉動、步數計數、字幕都會跟著伸縮，不必去調那些寫死的秒數。

## 8. 疊人像（步驟 8）

```bash
START=1.0 END=33.43 LABEL=樹懶老師 scripts/pip.sh 無配樂.mp4 動畫_配合旁白.mp4 旁白.mp4
```

`START`、`END` 抄 `旁白.json` 的值。目前定案的版位就是工具的預設值：

| 項目 | 值 | 為什麼 |
|---|---|---|
| 位置 | 右下角、貼底（底邊 y=1912、右邊距 40） | 動畫把畫面中段用滿了，只有字幕下方有空間 |
| 形狀 | 正圓、直徑 336、白外框 6px | 再大會壓到字幕 |
| 內容 | 整張畫面塞進圓裡，兩側用模糊的同一張補滿（`FIT=contain`） | 直式素材從頭到手佔滿整個高度，正方形裁切裝不下，講師要看得到手勢 |
| 名牌 | 講師稱呼，掛在圓框上緣（頭的上面），黃底深紅字白邊 | 跟動畫紅色主題的報名標籤同一套配色；放下緣被退回過 |
| 收框 | 結尾報名標籤彈出前淡出，聲音照常播完 | 不然圓框會蓋住 CTA |

這個位置在 IG Reels 的介面區裡（右下角會被按鈕列蓋到一部分），是講師看過之後決定的取捨。要檢查安全區加 `SAFE=1`。

**換了一支動畫，字幕位置可能不一樣，要重量。** 把整支動畫每一格的最亮值疊成一張圖，文字出現過的地方都會留下來：

```bash
ffmpeg -t <END> -i 動畫_配合旁白.mp4 -vf "format=gbrp,extractplanes=g,lagfun=decay=1" -update 1 text-map.png
```

紅底動畫的白字、黃字在綠色通道很亮（>140），背景很暗。**黃底主題不能用這個方法**，改用 `references/lessons.md` 第 25 條；名牌配色也要跟著主題換（第 26 條）。算圓框和名牌的範圍裡有幾個亮點，要是 0。01 量出來的字幕範圍是 y 1343–1500、x 111–955；直徑 380 以下壓到 0 個字幕像素，400 壓到 543 個，420 壓到 3,837 個。

## 9. 配樂與響度（步驟 9）

```bash
scripts/music.sh 成品/NN_片名_A.mp4 無配樂.mp4 music/曲.mp3
```

- 配樂用可商用的無版權音樂，來源與已經用過的曲目記在 [`references/music.md`](references/music.md)。**音樂檔不放進 repo**（授權不允許單獨轉發），只記出處。
- 一次做三四種調性各出一版讓講師挑，不要自己決定——好不好聽量不出來。
- 響度標準跟 dreamone-cube-reel 一致：成品 −16～−14 LUFS、峰值 ≤ −1 dBFS。配樂預設比人聲小 13 dB（`BED=13`）。
- 墊了音樂之後再回讀一次逐字稿：抄得出來代表人聲沒被蓋住。

## 10. 驗收與交付（步驟 10）

交件前逐項確認，每一項都要有量測或截圖，不能憑印象：

- [ ] `snap.py` 的報告全部乾淨
- [ ] `旁白.mp4` 回讀的逐字稿和 `聽到的` 逐字一致（同音字差異可接受）
- [ ] 成品回讀：每句都抄得出來，開口時間和 `旁白.json` 的錨點差在 ±0.3 秒內
- [ ] 圓框和名牌壓到的字幕像素是 0
- [ ] 每隔幾秒抽一格做成總覽圖，逐格看過：人臉比例、圓框位置、名牌、結尾標籤沒被擋
- [ ] 成品響度 −16～−14 LUFS、峰值 ≤ −1 dBFS
- [ ] 1080×1920、30 fps

回報時把**量不出來的事**講清楚：配樂合不合適、語氣、哪幾秒請講師特別聽一下。

交付後：

- 更新片單的狀態、長度、配樂。
- 對動畫專案的修改（時間軸掛鉤等）開分支推回動畫的 repo；這個 skill 的改進走這個 repo 的分支與 Pull Request。
