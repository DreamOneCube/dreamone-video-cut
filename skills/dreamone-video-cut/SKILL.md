# 夢想一號影片剪輯流程

把一批手機直拍素材（通常是 .MOV、1080p60 HEVC，偶爾 1440p）剪成一支 1920×1080、30fps 的橫式成品。
這份流程從《大師不藏私》斜轉系列實際剪出來，規則是通用的：換主題、換講師、換方塊、換成非系列影片都照用，
只有「標題、章節、詞彙表、版面開關」寫在 `config.json` 裡換掉。

執行位置依當次環境調整：Codex 可在本機完成規劃與編碼；原 CoWork 的雲端／Mac 分工與 180 秒限制是歷史環境條件，見 `references/environment.md`，不要直接套用到其他工具。先依 README 建立 Python 虛擬環境並安裝 `requirements.txt`。

## 流程總覽

1. **確認需求**（下一節的清單）——答案寫進 `config.json`
2. **取得素材**——使用者下載到 Mac 的專案資料夾，連給你
3. **探勘＋轉錄**——ffprobe、抽音訊、語音辨識（`scripts/asr.py`）
4. **寫 EDL**——讀辨識稿，決定順序、取哪個 take、跳剪哪裡（這是唯一需要判斷力的步驟）
5. **量音量**——`scripts/measure_gain.py`（Mac）
6. **規劃**——`scripts/build.py`（雲端）：產生版面 PNG、單元表、SRT/TXT
7. **給使用者看示意圖＋5 秒試剪**，確認後才全跑
8. **編碼**——`scripts/run.py`（Mac，一次一小段，反覆呼叫）
9. **串接＋檢查**——`run.py concat`、`run.py shots`，自己看過截圖檢查表再回報

## 1. 開工前要確認

能從素材、檔名、群組筆記推得出來的就自己推，推不出來的才問：

- **要出幾支成品、每支包含哪些素材**（例：「第二部」= `4-x` + `5-1`；「第一部」= 前言 + `1-x` + `2-x` + `3-x`）
- **每支的章節名稱與順序**（頂部進度條用，一支 3–6 章）。順序依**教學邏輯**：後面章節會用到前面教過的東西，就排在後面——不要照資料夾字母排序
- **標題文字**（例：`《大師不藏私》`；非系列影片可換成課程名，或留空）
- **版面**：要不要頂部章節條、要不要底部 CC 字幕黑區（預設都要）
- **講師稱呼與專有名詞**（公式名、手法名、零件名）——做成 `terms/<主題>.json`
- **字幕要直出還是要重寫**——預設**直出辨識稿**（見第 4 節）

## 2. 交付物（每支成品）

放在專案資料夾最外層：

| 檔案 | 內容 |
|---|---|
| `{名稱}_初剪_v1.mp4` | 1920×1080、30fps、H.264，**不燒字幕** |
| `{名稱}_字幕.srt` | 對應成品時間軸，可直接上傳 YouTube／平台當 CC |
| `{名稱}_字幕.txt` | 純文字，依章節分段（`【1. 章節名】`），一句一行 |

回報時附 6 格截圖檢查表、成品長度、跳剪了哪些地方、字幕需要校對的提醒。

## 3. 剪輯規則（通用）

- **一支成品 = 指定素材依章節順序合併。** 每支素材屬於一個章節；同章節的素材要相鄰。
- **同一段有多個 take**（檔名「第一次／第二次嘗試」）：比對辨識稿，用最完整、口條最順的那個，通常是最後一次。
- **補充素材**（檔名「…補充」「後半補充話語」）接在它補充的段落後面，不一定照檔名序號。
- **重複素材要抓出來**：例如「前言.mp4」可能就是某個開場 take 剪好的版本——比對辨識稿，同一段話不要出現兩次。
- **跳剪**只剪「話」有問題的地方：開頭吃螺絲、講錯重來、句子講一半放棄、孤立的「呢」「那。」、講師自己算錯重做、結尾多餘的收尾。剪點對齊辨識的段界（前後各留約 0.1 秒）。俯拍固定鏡位，跳剪不用轉場。**保守為上**：內容有意義就留。
- **保留不講話的示範段**——那是教學內容，不是空檔。
- **音量**：每支素材量 mean volume，加固定增益拉到 −19 dB（`measure_gain.py`）。不要用 loudnorm，分段編碼時它每段結果不同。
- **裁切**：預設上下各裁約 8%，影片縮到 1600 寬置中；先看縮圖確認不會切到手和道具。

## 4. 字幕規則

預設 **直出辨識稿，不改寫**，只做機械式清理（`scripts/subtitles.py`）：

- 簡轉繁（OpenCC `s2twp`），大陸用語改回台灣用語
- 專有名詞用詞彙表統一：`terms/common.json`（系列共用：大師不藏私、魔術方塊、夢想一號）＋ 該主題的檔案（例：`terms/skewb.json`）。新主題時先建名詞表，再把辨識稿裡看到的錯聽逐一加進去
- 拿掉純語助詞（呃、OK、句尾的啊／哦／哈／呢），其餘保留原句；中英文之間加半形空格
- 每行 ≤ 26 字，依標點切行，時間按字數比例分配；字幕不因編碼分段而重複。跨跳剪點的辨識句會顯示校對提醒

使用者明確要求「專業字幕」時才逐句改寫（寫在 EDL 的字幕欄，不改辨識稿），那時改用 Opus 級模型。
不論哪種，**字幕一律不燒進影片**，只交 SRT／TXT。

## 5. 版面（預設，全系列統一）

```
┌────────────────────────────────────────────┐ 0
│ 1 開場介紹  2 一步底  3 多步底  4 實戰演練  5 結尾 │  頂部章節條 176px（#0E1116）
│ ███████████●──────  ─────  ──────────  ──  │  紅色進度隨時間走，白點＝目前位置
│ 00:00     01:00                       14:17│
├────────────────────────────────────────────┤ 176
│        ┌──────────────────────┐            │
│        │   影片 1600×754 置中   │            │  左右黑邊與黑底拍攝連成一片
│        └──────────────────────┘            │
├────────────────────────────────────────────┤ 930
│ [Logo]          （留給平台 CC）      《標題》 │  底部純黑 150px
└────────────────────────────────────────────┘ 1080
```

- **字體**：全部用 jf open 粉圓體（`jf-openhuninn-1.1.ttf`，取得方式見 `assets/README.md`）
- **章節條**：每章一段、寬度依時長比例，最窄 210px（短章節不會擠在一起）；目前章節白字 32px，已過灰字、未到暗灰
- **Logo**：夢想一號橫式白字 Logo，左下、無底色
- **標題**：右下、白字、無描邊無底色；不放集數、不放章節名
- 版面開關：`layout.top_strip=false` 拿掉章節條、`layout.cc_band=false` 拿掉底部黑區（影片放大，Logo 與標題改直接壓在影片角落）

## 6. 實際操作

工作檔放專案資料夾下的 `work/`（Mac 上不能刪檔，換版本就開新子資料夾）。

**3. 探勘＋轉錄**
```bash
# Mac
ffprobe -v error -show_entries format=duration:stream=width,height,r_frame_rate -of csv=p=0 <clip>
ffmpeg -i <clip> -vn -ac 1 -ar 16000 -c:a pcm_s16le work/audio/<id>.wav     # 把 wav stage 到雲端
# 雲端（第一次要先照 asr.py 開頭的說明裝模型）
python3 scripts/asr.py --models <模型資料夾> work/audio/*.wav             # 每支輸出 <id>.json
```

**4. 寫 EDL**（`edl.json`，雲端）——每支素材一筆：
```json
{"clip_id": "4-4b", "path": "drive-download-…/第二部-…/4-4實戰演練（沒有連色）.MOV",
 "chapter": "實戰演練", "tin": 1.94, "tout": 363.63, "segs_file": "audio/4-4b.json",
 "drops": [[152.1, 152.7], [250.3, 266.9]]}
```
把每支的辨識段落印出來逐段讀，再決定 `tin/tout/drops`。`path` 相對於 Mac 上的專案資料夾。

**5. 量音量**（Mac）：`python3 scripts/measure_gain.py --root "<專案>" work/edl.json`（素材多就用 `--only` 分批，每次呼叫 < 180 秒）

**6. 規劃**（雲端）：`python3 scripts/build.py --config config.json --edl edl.json --out work/plan_<名稱>`
→ 將 `scripts/run.py` 複製到 plan 資料夾（和 `units.json` 同層）。CoWork 跨機執行時，再把整個 plan 資料夾送回 Mac；本機執行可直接使用。

**7. 試剪**（Mac）：`python3 run.py --root "<專案>" test <unit_id> 0 5`
→ 抽一張畫面當示意圖，連同 5 秒 mp4 給使用者確認。**確認前不要全跑。**

**8. 編碼**（Mac，反覆呼叫直到全部完成）：`python3 run.py --root "<專案>" run`

**9. 收尾**（Mac，分開兩次呼叫）：`run.py … concat`，然後 `run.py … shots` → stage `check_sheet.jpg` 回來自己看。

## 8. 模型建議

- 字幕直出（預設）：**Sonnet 就夠**——判斷只剩選 take 和跳剪，其餘是照流程跑腳本。
- 要逐句改寫成專業字幕、或素材很亂需要大量重排：用 **Opus**。

## 9. 環境限制與坑

詳見 `references/environment.md`。以下是原 CoWork 環境的三個限制，先核對當次工具是否相同：

1. **device_bash 每次呼叫 180 秒上限，背景程序會被砍**——所以 `run.py` 每次只做約 25 秒的新工作就停，靠 `.done` 標記續跑。
2. **Google Drive 檔案下載不到**（雲端和 Mac 工作區都擋）——請使用者自己下載到 Mac，再連資料夾給你。
3. **長片串接不要加 `+faststart`**——2 GB 的檔案重寫會超時。
