# 夢想一號方塊說明型 Reel

一支只回答一個問題的直式短片：中間一顆 3D 方塊示範，上方是算式或重點，下方是逐句字幕。
這份流程從 2026 年 11 月的樣片〈4,325 京種狀態是怎麼算出來的？〉做出來，經過三輪回饋定下版面與規則。
`template/` 就是那支樣片的完整專案，新題目從它複製後改稿，不要從零寫。

## 0. 三條不能破的規則

1. **方塊只能由程式算出來。** 不用 AI 生圖、不手繪、不直接上色。每一格畫面的方塊狀態都來自 `lib/cube-engine.js`，引擎每次建置都會和 cubing.js 逐張貼紙比對。AI 生成的方塊幾乎都是不可能存在的狀態。
2. **每一顆方塊都帶夢想一號的三角形 Logo。** 只用三角形、不含字，預設印在白色中心塊（和實體方塊一樣）；鏡頭拍不到白色面時，改放在看得到的中心塊。Logo 只用原檔等比縮放，不重畫。
3. **預設靜音。** 成品沒有旁白、配樂、音效。聲音的做法還沒定案，沒有被要求就不要加；現況與接手方式見 `references/sound.md`。

## 1. 成品規格

| 項目 | 規格 |
|---|---|
| 畫面 | 1080×1920、30 fps、H.264 MP4 |
| 長度 | 約 60 秒（58–60 秒的節奏已確認可以） |
| 聲音 | 無（預設靜音，成品不含音軌） |
| 內容 | 一支只講一個問題，不需要真人入鏡 |
| 交付 | 影片＋一張總覽圖，檔名以 `YYMMDD_` 開頭 |

## 2. 流程

1. **選題。** 一支一個問題，題材清單見 `references/topics.md`。
2. **複製範本。** 把 `template/` 整個複製成新資料夾（`YYMMDD_方塊Reel_題目`），改 `meta.json` 的名稱，跑 `npm install`。
3. **寫規格。** 把 `SPEC.md` 改成這支的目標、分鏡與禁用項。
4. **寫稿。** 改 `lib/script.js`（第 5 節的文案規則）。
5. **排方塊動作與數字。** 改 `lib/reel-data.js`：每個動作掛在某一句稿子上，數字由程式算。
6. **排上方資訊。** 改 `tools/build.mjs` 第 4 段的 `top` 清單與 `tools/words.template.html`。
7. **建置與檢查。** `npm run build`（最後會自動跑方塊驗證）→ `npm run check` → 截圖逐段看。
8. **算圖與交付。** 算出 MP4、做總覽圖、照第 9 節的清單驗收。
9. **發布前實體覆核。** 請講師拿實體方塊照畫面轉一次，確認一致才發布。

```bash
npm install
npm run build
npm run check
npx --yes hyperframes@0.9.33 snapshot --at 1,8,20,35,45,58
npx --yes hyperframes@0.9.33 render -o "YYMMDD_方塊Reel_題目_v1.mp4"
ffmpeg -i "YYMMDD_方塊Reel_題目_v1.mp4" -vf "fps=1/5,scale=270:-1,tile=6x2" -frames:v 1 "YYMMDD_方塊Reel_題目_總覽圖_v1.png"
```

需要 Node 22 以上（在 Node 24 實測）與 ffmpeg。製作時搭配 HyperFrames 的 Skill（`hyperframes`、`hyperframes-cli`）使用；本 Skill 只規定夢想一號方塊短片特有的部分。

新題目先交一支樣片，確認後才批次做同系列。同系列沿用本頁已定的外觀，不必每支重新提案。

## 3. 版面（1080×1920）

| y 範圍 | 內容 |
|---|---|
| 0–168 | 空（系統列） |
| 168–231 | 橫式 Logo，左上角（left 60、寬 360） |
| 345–610 | 上方資訊：開場標題、計數、算式、答案、結尾大數字 |
| 約 607–1225 | 方塊（寬約 540px，中心約 y 915） |
| 1312–1490 | 字幕（逐句，最多兩行） |
| 1490–1920 | 只有地板；Reels 的帳號名稱、說明文字、音樂標籤會蓋在這一段 |

已確認的版面規則：

- **橫式 Logo 放在安靜的地方。** 不貼著標題或字幕，四周至少空 100px。
- **字幕和中間的主體要有明顯空隙。** 約 95px；20px 被認為太近。主體換成別的東西也一樣。
- **底部不能看起來一大片空。** 最底下約四分之一要留給 IG 介面，所以用打亮的地板、地板格線與字幕把它填成「場景的一部分」。
- 字幕框 left 100、寬 840，右側留給 IG 的按鈕。
- 文字落定後不再動。

## 4. 外觀

- **場景**：3D 攝影棚裡的一顆實體方塊。黑色本體、圓角貼紙、暖色主光加補光、地板有真實陰影。
- **底色**：深寶藍 `#0f2f7a`，方塊腳下一塊打亮的地板 `#2458c8`，地板格線透明度 11%。
- **文字**：白 `#ffffff`，重點黃 `#ffd84a`，「不可能」專用紅 `#ff5a52`。
- **字型**：jf open 粉圓 2.1。標題 88px、大數字 124–150px、算式 40–46px、字幕 66px、小標 28px。
- **方塊配色**：白頂、綠前、紅右、橘左、藍後、黃底。
- **動態**：轉動用三次方緩入緩出；數字由大落定 0.4 秒；字幕 0.08 秒淡入淡出，不做動畫。
- **禁用**：莫蘭迪色、兒童插畫風、發光霓虹、玻璃卡片、生硬擁擠的排版、破圖。

## 5. 文案

- **口語，但保有專業。** 短句、一句一個意思，像老師在旁邊講（「最後一個就沒得選」）。精確的數字與算式放在畫面上方，字幕講人話的近似值（「四萬多種」）。
- `say` 寫完整講法，數字用國字；`show` 是字幕，數字用阿拉伯數字，重點用 `<em>` 標黃。字幕每行最多約 12 個字、最多兩行。
- **數字不手打。** 畫面上的每個數字都由 `lib/reel-data.js` 算出來（大數用 BigInt），驗證腳本會重算一次。
- **會變動的事實當天查證**：世界紀錄、WCA 規則在製作當天對官網，不靠記憶。
- 給家長看的題目不編造研究或數據。

## 6. 方塊正確性

- 狀態只能由「還原狀態＋轉動代號」產生。要示範不可能的狀態（只扭一個角、只翻一個邊、只交換兩塊）時，用引擎的 `twist`／`flip`／`swap`，並在腳本裡標檢查點，讓驗證確認它「真的不合法」以及之後「確實復原」。
- 畫面上的代號和動畫共用同一份資料，字幕和畫面不會對不上。
- `npm run verify`（建置時自動跑）檢查四件事：18 種基本轉動＋500 組 30 步隨機公式與 cubing.js 逐張貼紙一致；黃金測試；腳本每個檢查點的合法性；畫面上的每個數字。**沒有全部通過就不能交付。**
- 新腳本有新的檢查點或新數字時，在 `tests/verify.mjs` 補上對應的斷言。
- 引擎目前只支援六個面的基本轉動（U D L R F B 與 `'`、`2`）。要用中層（M E S）或整顆轉向（x y z），先擴充引擎並補上和 cubing.js 的對照測試。
- 實拍畫面不可鏡像：左右翻轉後紅橘會對調，順時針會變逆時針。

30 秒人工檢查：還原狀態（白頂綠前）做一次 R，頂面右排應該變成綠色。畫面不是這樣就是錯的。

## 7. 時間軸

稿子是時鐘。每一句有自己的長度，方塊動作、上方數字、字幕都掛在句子上（`L("句子 id").at(0.5)` 是那一句進行到一半的時間），不直接寫秒數。改稿後重新建置，整支影片會跟著重排。

- 靜音時句長用字數估：每個字 0.2 秒，句中每個停頓 0.28 秒。
- `gap`：這句結束後停多久再進下一句（預設 0.22 秒）。
- `hold`：從這句開始算起，至少過幾秒才進下一句，用來留時間給方塊動作。

## 8. 改什麼要改哪裡

| 要改什麼 | 改哪裡 |
|---|---|
| 稿子、字幕、每句停多久 | `lib/script.js` |
| 方塊動作、畫面數字、事件時間點 | `lib/reel-data.js` |
| 上方資訊區放什麼 | `tools/build.mjs` 第 4 段的 `top` 清單 |
| 上方資訊區的版面、字級、進出場 | `tools/words.template.html` |
| 字幕的位置與字級 | `tools/captions.template.html` |
| 方塊外觀、鏡頭、燈光、三角形 Logo | `compositions/cube.html` |
| 背景與地板 | `tools/index.template.html` |
| 方塊規則（除非擴充轉動種類，否則不要動） | `lib/cube-engine.js`、`tests/verify.mjs` |

`index.html`、`compositions/words.html`、`compositions/captions.html`、`lib/timing.js` 是建置產生的，不要手改。

## 9. 交付前逐項檢查

- [ ] `npm run build` 最後的方塊驗證全部通過
- [ ] `npm run check` 0 個錯誤，每個警告都看過（已知可忽略的見下方）
- [ ] 截圖逐段看過：Logo 位置、字幕與方塊的空隙、沒有破圖、文字都在安全範圍內
- [ ] 每一顆方塊都看得到三角形 Logo
- [ ] 成品是 1080×1920、30 fps，而且不含音軌（`ffprobe` 確認）
- [ ] 交付影片與總覽圖，檔名以 `YYMMDD_` 開頭
- [ ] 發布前由講師用實體方塊覆核

已知可忽略的檢查警告：

- `film_silent`：靜音是預設，不是漏做。
- `line_unread`（乘法鏈的小標）：誤判。乘法鏈的每一項都會留到答案出現，截圖可確認。

## 10. 聲音（未定案）

2026 年 11 月的回饋是「聲音還不正確，先不要有聲音」，所以範本預設 `audio: false`。試過的做法、已經寫好可以打開的音軌流程、需要的素材與授權，以及接手的人要決定的事，都在 `references/sound.md`。

**之後把聲音做法定下來的人，請更新 `references/sound.md`、本節與第 0 節第 3 條，並視決定調整範本的 `audio` 預設值。**

## 11. 已知限制

- 範本是一支完成的樣片，不是空白框架：上方資訊區的內容分散在 `tools/build.mjs` 與 `tools/words.template.html`，換題目時兩邊都要改。
- 三角形 Logo 目前只印在白色中心塊。
- HyperFrames 版本固定在 0.9.33，升級後要重新驗證畫面。
